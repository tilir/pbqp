# C API 1.0 reference

The API reference is generated by Doxygen directly from
[include/pbqp.h](../include/pbqp.h). The public types, functions, numeric enum
values, ownership rules, callback contracts, and failure semantics are documented
there. [include/pbqp.hpp](../include/pbqp.hpp) supplies the generated C++ reference.
These headers are the source of truth; do not maintain a second handwritten
symbol reference. The [programmer's guide](programmers_guide.md) covers integration,
complete examples, and Python/Ruby bindings.

## Generate the reference

Install Doxygen 1.9 or newer, then enable the optional documentation target in
an already configured build tree:

```sh
cmake -S . -B build -DPBQP_BUILD_DOCS=ON
cmake --build build --target docs
```

Open `build/docs/html/index.html`. No Graphviz or LaTeX is needed. The normal
library/tool build does not require Doxygen and never downloads it. Documentation
warnings fail the target. Release CI generates and uploads the HTML reference
as the `api-reference` artifact.

## Version and compatibility

The initial stable C API is **1.0.0**. Header constants
`PBQP_API_VERSION_MAJOR`, `PBQP_API_VERSION_MINOR`, and `PBQP_API_VERSION_PATCH`
describe the header; `pbqp_get_api_version` reports the linked library's version.
The independent `PBQP 1` file-format signature is not an API version.

API 1.x preserves existing function signatures, numeric enum values, public
struct layouts and field types, and ownership rules. Compatible additions use a
minor version; compatible fixes use a patch version. Breaking those contracts,
including adding fields to an existing public struct, requires a new major API
version. Shared libraries use VERSION `1.0.0` and SOVERSION `1`.

Binary compatibility requires the same platform ABI and architecture. Use normal
C layout and calling conventions without short-enum or packing options. Native
`size_t`, pointers, and enum representations are not portable across architectures.
The C boundary exposes no C++ standard-library types. The header-only C++ wrapper
is rebuilt with its consumer and does not promise a cross-toolchain C++ ABI.
