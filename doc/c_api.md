# C API 2.0 reference

The API reference is generated by Doxygen directly from
[include/pbqp.h](../include/pbqp.h). The public types, functions, numeric enum
values, ownership rules, callback contracts, and failure semantics are documented
there. [include/pbqp.hpp](../include/pbqp.hpp) supplies the generated C++ reference.
These headers are the source of truth; do not maintain a second handwritten
symbol reference. The [programmer's guide](programmers_guide.md) covers integration,
complete examples, and Python/Ruby bindings.

## Generate the reference

Install Doxygen 1.9 or newer, then enable the optional documentation target in
an already configured build tree:

```sh
cmake -S . -B build -DPBQP_BUILD_DOCS=ON
cmake --build build --target docs
```

Open `build/docs/html/index.html`. No Graphviz or LaTeX is needed. The normal
library/tool build does not require Doxygen and never downloads it. Documentation
warnings fail the target. Release CI generates and uploads the HTML reference
as the `api-reference` artifact.

## Version and compatibility

The current C API is **2.0.0**. Header constants
`PBQP_API_VERSION_MAJOR`, `PBQP_API_VERSION_MINOR`, and `PBQP_API_VERSION_PATCH`
describe the header; `pbqp_get_api_version` reports the linked library's version.
The independent `PBQP 1`/`PBQP 2` signatures are not C API versions.

API 2.x preserves existing function signatures, numeric enum values, public
struct layouts and field types, and ownership rules. Compatible additions use a
minor version; compatible fixes use a patch version. Breaking those contracts,
including adding fields to an existing public struct, requires a new major API
version. Shared libraries use VERSION `2.0.0` and SOVERSION `2`.

Binary compatibility requires the same platform ABI and architecture. Use normal
C layout and calling conventions without short-enum or packing options. Native
`size_t`, pointers, and enum representations are not portable across architectures.
The C boundary exposes no C++ standard-library types. The header-only C++ wrapper
is rebuilt with its consumer and does not promise a cross-toolchain C++ ABI.

## Migration from API 1.0

Version 2 replaces the fixed fields of `pbqp_solve_options` with a borrowed,
open map of tagged key-value entries. Use the inline typed option constructors
from `pbqp.h`; keys and pointer/string payloads stay borrowed through the call.
The last entry for a key wins. Each solver consumes its understood keys and
warns for unrelated keys; wrong types or values for consumed keys return INVALID.
The `warnings` callback (falling back to diagnostics) receives warnings outside
DFS. With neither callback the library stays silent. Set the BOOL key
`warnings-as-errors` to make unknown keys INVALID before search, even without a
warning sink.

There is now one B&B entry, `pbqp_solve_branch_and_bound`, and one dispatcher
selector, `PBQP_SOLVER_BNB`. The separate optimized entry and BNBOPT selector are
removed. Select `optimization-level=2` to request the former optimized defaults;
missing options select O1. Explicit boolean overrides apply after the profile.
The CLI names `bnb` and `bnbopt` select defaults O1 and O2 for this same engine.

Recompile clients and update their option construction. Python/Ruby bindings
verify major version 2 before accessing any layouts. Problem/solution layouts,
ownership, status values, and reference float semantics are unchanged. Reading
remains compatible with PBQP 1; writing now uses compact PBQP 2 with shared
dense/sparse matrices. See the [programmer's guide](programmers_guide.md) for map examples and
[optimization profiles](bnbopts.md#optimization-profiles-and-overrides) for CLI controls.
